# 传输通道与预检

一次交接只允许一条通道。按以下优先级探测，锁定后记录所选通道；同一交接内不得切换。

## 通道优先级

1. `codex-in-app-browser`（仅当宿主提供 ChatGPT 桌面应用与 `browser:control-in-app-browser` 能力）
   沿用 `codex-bridge-chatgpt` 的既定路径：只使用 Mac 或 Windows ChatGPT 桌面应用的内置浏览器。宿主运行环境明确表明是 CLI、IDE、cloud、Linux 或其他不支持该能力的表面时，本通道不可用。
2. `user-chrome`（其余宿主优先）
   用宿主的浏览器控制能力接管用户已登录的 Chrome：优先连接正在运行的 Chrome，其次以用户默认配置目录启动一个可见窗口。判定标准：页面可见、地址为 chatgpt.com 且已处于登录态。禁止新建空白配置、隐身窗口或隔离 profile 来冒充本通道——那不是用户的会话。宿主能力只能提供隔离浏览器环境时，本通道视为不可用，如实跳到第 3 条，不得借道。
3. `host-browser-use`（回退）
   第 2 条无法连接或启动时，用宿主内置 browser-use 能力打开它自带的可见浏览器并访问 chatgpt.com。未登录则报告 `NEEDS_CHATGPT_LOGIN`，请用户在该可见窗口人工登录一次后继续原任务。

三条通道都禁止：无头、后台、定时、容器化、并行、代理、隐身、验证码破解、反检测执行；禁止访问 cookie、local storage、session storage、私密端点与隐藏鉴权数据。

## Preflight 状态（恰好返回一个）

- `NEEDS_BROWSER`：三条通道都不可用，或宿主没有任何可见浏览器控制能力。
- `NEEDS_CHATGPT_LOGIN`：所选通道的 ChatGPT 页面可见处于未登录状态。
- `NEEDS_MODEL_SELECTION`：用户指定的模型未在可见 UI 中选中或不可用。
- `NEEDS_SITE_PERMISSION`：宿主对该站点或浏览器的访问等待用户授权。
- `READY`：登录态、指定模型与通道能力均已可见满足。

需要人工接管时，原任务与当前任务包草稿保留在本地。请用户在可见页面完成登录、模型或权限步骤，不要在对话中提交凭据。用户下一条消息后，只复查易变的浏览器状态并继续原任务。

## 发送与回收纪律

发送前记录本地 UI 摘要：chatgpt.com 来源、已认证账号 UI、所选模型、无拦截状态。交接完成后再次记录相同事实。DOM 检查可用于核对可见 UI 状态，但不得用于提取响应正文。

在可见输入框填充合同并触发 Send 恰好一次。观察用户消息是否出现；绝不再次触发 Send。提交结果不确定即本次交接终局阻塞。

`reasoning`：等待一个完整回答，用页面可见的复制回答动作恰好一次。剪贴板未变化、回答不完整或标记/标题无效即停止。禁止从 DOM 提取正文。

`image`：等待生成完成（停止按钮消失、约定数量的图片全部渲染完成），用页面自带的下载/保存动作把图片存入任务文件约定的目录；页面提供复制图片或另存动作时同样恰好使用一次。保存后立即运行格式校验。

遇到登录、CAPTCHA、速率限制、异常活动、账号受限、权限、控件歧义或选择器漂移状态即停止，不得绕过。
