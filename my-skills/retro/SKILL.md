# Retro

复盘的对象是**工作环境与流程**，目的是降低下一次任务的搜索、误解或验证成本。主动检查本身就是复盘的一部分：不必等事故或重复错误才查护栏。默认不直接改正式业务代码、项目规则、lint/CI 或真实外部系统；但可以执行已有安全检查，并在隔离临时目录构建、试运行候选检查，把产物和证据交付审阅。若已有授权覆盖实施，按项目工具链直接完成，不重复询问。

## 1. 选择证据

使用用户指定的会话或当前会话。查看本会话工具输出、diff、命令结果和错误；若相关材料已保存在仓库或明确路径，直接读取。没有权限或可用路径时，说明证据限制，不扫描凭据或无关个人数据。检查当前仓库的 `AGENTS.md`、README/贡献说明、已有 lint、类型检查、测试命令、CI、Git hooks 和 review 指引，以当前文件与脚本为准。默认盘点并实际运行与复盘范围相关、可安全执行的现有检查；记录命令、结果、覆盖范围和缺口。CI 若不能本地运行，检查可取得的当前运行证据；没有可用结果就标记未验证，不能把配置存在当成通过。只读检查可直接运行；会写真实数据、触发外部副作用或产生明显费用的操作按已有授权和工具说明处理。无 hook、无 CI、已有检查未接线或失效，都是可以由当前仓库事实确认的发现，不必等错误发生。

## 2. 检查改进方向

结合会话、当前仓库事实和本轮检查结果，主动查找以下改进机会；不要求问题已经在会话中实际发生：

- **导航**：是否难以找到契约、入口或数据源？考虑短指针、索引或清晰命名。
- **确定性护栏**：语法、禁止 API、目录约束等固定规则若能机械判断，优先复用或构建确定性检查，并试运行验证；不要只补一条文字提醒。证据可以来自当前规则和仓库结构，不限于已发生错误。
- **判断标准**：上下文权衡适合写入项目已有的 review 指引，不要硬编码成误报很多的脚本。
- **信息可达性**：是否缺少日志、只读接口、测试夹具或文档，导致结论只能猜测？建议最小可行入口。
- **流程与工具成本**：是否存在重复等待、昂贵命令或不必要并行？给出具体节省点。
- **无效指令**：哪些现行说明没有改变行为或与其他规则冲突？引用冲突并建议删除或改成可验证动作。

机械检查按“主动查漏 → 构建或复用检查 → 实际运行取证 → 评估覆盖与误报 → 决定长期接入、合并或调整”推进。成本和维护负担在首次试运行取得证据后评估，不能作为不做检查的前置门槛；有价值的独立冗余可以保留，不因已有一项检查就自动压掉其他覆盖。

对新建或调整的检查，使用隔离 fixture 同时放入已知违规样例和合法样例，实际运行确认能发现违规且不过度误报。若检查未发现问题、漏报、误报或无法运行，记录实际结果、范围和原因；静态阅读或推演不算执行通过。可在隔离临时目录产出候选脚本、配置或 fixture 并交付证据，但未获实施授权时不把候选静默接入正式 hook、CI 或项目配置。已有实施授权覆盖接入时，按项目既有工具链实施并运行验证。

不要把全局策略写进本仓通用 `AGENTS.md`：本机全局策略有唯一主源和分发流程；涉及全局规则时指出准确主源与同步流程。

## 3. 呈现结果

按影响列出发现及建议，给出证据位置、已运行检查及真实结果、覆盖与缺口、具体成本/风险、最小改动和预期效果；区分事实、推测和仍待验证项。机械检查建议附候选产物与隔离 fixture 的运行证据；人工判断建议落到项目现有 review 指引。若检查后没有值得长期接入的改动，说明已盘点和运行的范围、为何未接入及尚未知项，不制造任务，也不把未检查写成没有问题。
