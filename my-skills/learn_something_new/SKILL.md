# learn_something_new — 系统化学习辅助工具

> **来源备注**：本 skill 整理自公众号「数字生命卡兹克」分享的提示词模板，结合实际使用经验做了结构化封装与补充。

四种方法按「理解 → 模仿 → 深度研究 → 验证」递进，可单独使用，也可组合使用。

---

## 方法一：双层解释法

**用途**：面对完全不懂的概念，分别从"小白视角"和"专家视角"两次解释，避免停留在"好像懂了"的层面。

**适用场景**：
- 刚接触一个新概念、新术语
- 听别人讲了但说不清自己到底懂没懂
- 需要向别人转述——转述不出来 = 没真懂

**触发词**：「我想学 X」「帮我解释 X」「X 是什么意思」「搞懂 X 的原理」「X 是怎么运作的」

**使用方式**：把下面的模板整段发给 AI，把【】里的内容替换成你想要学习的具体概念或问题。

### 提示词模板（直接可用）

```
我想学习的是：【填写概念或问题】。请分两层解释：

第一层，小白版：用生活化语言和具体例子，让无基础者也能听懂。

第二层，专业版：使用准确术语，讲清核心机制、适用边界和常见误解。

最后整理：
1）小白说法与专业术语对应关系；
2）最易理解错的地方；
3）3个检查是否真正理解的问题。
```

### 输出结构

AI 会按以下结构返回，你可以对照自查：

1. **小白版解释** — 生活化语言 + 具体例子
2. **专业版解释** — 准确术语 + 核心机制 + 适用边界 + 常见误解
3. **整理部分**：
   - 小白说法 ↔ 专业术语对应表
   - 最易理解错的地方（通常 2-3 条）
   - 3 个自检问题（能答上来 = 真懂了）

### 使用技巧

- **先看小白版，再看专业版**。如果小白版都看不懂，说明例子不够具体，让 AI 换一个更贴近日常生活的例子。
- **自检问题一定要自己答一遍**。能答上来 ≠ 记住了，要能用自己的话复述才算懂。
- **最易理解错的地方是最有价值的部分**。它往往揭示了你脑中已有的错误预设。

## 方法二：反向拆解

**用途**：看到优秀作品/网站/方案，想模仿学习其优点。

**适用场景**：
- 看到一个做得很好的网站、产品、文章、方案
- 想知道「它为什么好」而不是「它是什么」
- 需要把别人的经验转化成自己的可操作方法

**触发词**：「拆解这个」「分析一下这个范例」「它是怎么做到的」「这个好在哪」「模仿这个」「参考这个做法」

**使用方式**：把下面的模板整段发给 AI，把【粘贴成品】替换成你看到的优秀范例（可以是链接、截图描述、原文粘贴），把【填写目标】替换成你想学会的具体能力。

### 提示词模板（直接可用）

```
我想拆解的优秀范例是：【粘贴成品】。我想学会的是：【填写目标】。请先一句话说明它解决的问题，再反向拆解为何有效。

重点分析：
1）服务谁、目标；
2）结构或流程；
3）拉开质量差距的关键选择；
4）完成标准；
5）可迁移规律与仅限本案例的细节。

最后输出：
1）3-5条可复用规律；
2）操作清单；
3）最值得先尝试的小练习。
```

### 输出结构

1. **一句话问题定义** — 它到底解决了什么问题
2. **五维拆解**：
   - 服务谁、目标（用户画像 + 诉求）
   - 结构或流程（它是怎么组织起来的）
   - 拉开质量差距的关键选择（那些「如果换一种做法就会差很多」的决策点）
   - 完成标准（什么算做好了）
   - 可迁移规律 vs 仅限本案例的细节（分清楚哪些能复用、哪些是特定情境下的）
3. **三件输出**：
   - 3-5 条可复用规律（能用到你自己的项目里）
   - 操作清单（下一步动手做什么）
   - 最值得先尝试的小练习（低成本验证，快速获得反馈）

### 使用技巧

- **范例要给够信息**。只发一个链接，AI 只能猜。尽量附上你实际看到的界面、文案、数据，或者至少描述清楚你印象最深的部分。
- **「关键选择」是整个拆解的核心**。不要停在「它做了 A、B、C」，要追问「为什么选 A 不选 B」。
- **小练习要小到 15 分钟能做完**。拆解完不练一遍，规律还是作者的。

## 方法三：横纵分析法

**用途**：深度、系统研究某产品/公司/技术/行业，需配合 AI 深度研究功能使用。

**适用场景**：
- 需要写一份有依据的研究报告
- 想真正理解一个行业/公司的来龙去脉，而不是只看几篇摘要
- 需要判断一个领域未来会怎么走

**触发词**：「深度研究 X」「横纵分析 X」「全面分析 X」「X 的前世今生」「X 未来会怎么发展」「写一份关于 X 的研究报告」

**使用方式**：把下面的模板整段发给 AI，把【填写对象】替换成你要研究的具体对象。此方法需要 AI 具备深度研究能力（联网搜索、多源交叉验证），建议在支持长上下文和联网的对话中使用。

### 提示词模板（直接可用）

```
研究对象是：【填写对象】。请使用横纵分析法完成可追溯深度研究（截止执行当天）。

纵向：诞生背景与推动者、重要转折、早期选择演化的能力与包袱。

横向：选对比对象及理由、统一维度比较优劣、市场选择理由。

合轴判断：历史约束如何影响未来、3条未来路径及预警信号。

证据规则：优先一手来源、就近标注来源日期、事实推断观点分开、冲突并列呈现、无证据写"暂未核实"。

输出顺序：核心结论、关键时间线、横向对比表、详细分析、未来判断、待确认问题。

报告 10000～30000 字，语言通俗。
```

### 输出结构

1. **核心结论** — 一句话 + 展开，先给答案再给过程
2. **关键时间线** — 诞生背景 → 推动者 → 重要转折 → 早期选择 → 演化出的能力与背负的包袱
3. **横向对比表** — 选对比对象 + 理由，统一维度比较优劣，市场为什么选了它
4. **详细分析** — 纵向和横向的展开论述
5. **未来判断** — 历史约束如何影响未来，3 条未来路径，每条路径的预警信号
6. **待确认问题** — 研究中没能核实的部分，明确标注「暂未核实」

### 使用技巧

- **一手来源优先**。能拿到原始数据、官方文档、当事人访谈，就不要用二手摘要。
- **来源日期要就近标注**。研究类内容最容易过时，每个事实都要能追溯到「哪年哪月的什么来源」。
- **事实和观点分开**。「X 公司 2023 年收入 100 亿」是事实，「X 公司因此会继续增长」是观点，两者不要混在一起。
- **冲突并列**。不同来源说法矛盾时，不要自己选边站，把两种说法都列出来，标注各自来源。
- **未来路径要给预警信号**。不是「会变好」或「会变坏」，而是「如果出现 X 信号，说明走的是 A 路径」。

## 方法四：事实核查

**用途**：对一个观点、结论、数据或方案进行可信度审查——把它拆成事实、推论和价值判断，逐层核查。

**适用场景**：
- 听到一句「听说 X 会暴涨/会崩盘」，不知道该不该信
- 看到一份报告、一篇文章、一个方案，想判断它的结论站不站得住
- 需要决定「这个说法我可以相信到什么程度」，然后据此做决策

**触发词**：「这个说法是真的吗」「帮我核查一下」「这个数据靠谱吗」「X 的结论可信吗」「帮我验证一下这个观点」

**使用方式**：把下面的模板整段发给 AI，把【粘贴观点、结论、数据或方案】替换成你想要核查的具体内容。此方法需要 AI 具备联网搜索能力，建议在支持联网的对话中使用。

### 提示词模板（直接可用）

```
我要核查的说法是：【粘贴观点、结论、数据或方案】。

请先把它拆成：
1. 可以被外部验证的事实；
2. 从事实推出的结论；
3. 其中包含的价值判断。

对于事实部分，请联网核查来源、样本、时间和完整上下文，并标记为：
1. 已证实；
2. 基本成立，但需要收窄；
3. 存在争议；
4. 证据不足；
5. 明显错误。

在假设相关事实成立的情况下，继续检查：
1. 这些事实能否推出当前结论；
2. 是否藏着未经验证的假设；
3. 是否混淆相关性和因果关系；
4. 是否遗漏了其他解释或关键信息；
5. 结论在什么条件下成立或失效。

最后请输出：
1. 哪些事实可信，哪些需要修正；
2. 推理链中最关键的漏洞；
3. 补强后的最合理版本；
4. 我目前可以相信到什么程度。
```

### 输出结构

1. **三层拆解**：
   - **事实层**：可以被外部验证的陈述（数据、事件、可复现的结果）
   - **推论层**：从事实推出的结论（逻辑链条）
   - **价值判断层**：隐含的偏好、立场、「应该怎样」的预设
2. **事实核查表**：每条事实标注可信度标记
3. **推理链审查**：在假设事实成立的前提下，检查逻辑是否成立
4. **四件输出**：
   - 哪些事实可信，哪些需要修正
   - 推理链中最关键的漏洞
   - 补强后的最合理版本
   - 目前可以相信到什么程度（给出置信度和适用边界）

### 事实可信度标记

| 标记 | 含义 | 行动 |
|------|------|------|
| ✅ 已证实 | 多个独立一手来源一致确认 | 可直接使用 |
| ⚠️ 基本成立，但需要收窄 | 主流来源支持，但样本/范围/时间有局限 | 使用时注明边界 |
| 🔶 存在争议 | 不同来源说法矛盾，或学界/业界有分歧 | 并列呈现，不自行选边 |
| ❓ 证据不足 | 只有个别来源，无法交叉验证 | 标注「暂未核实」，不作为依据 |
| ❌ 明显错误 | 与可靠来源直接矛盾，或来源本身不可信 | 修正或弃用 |

### 推理链审查清单

在假设事实成立的前提下，逐项检查：

1. **能否推出结论** — 事实和结论之间的逻辑跳跃有多大？中间有没有跳步？
2. **隐藏假设** — 推理中是否预设了未经验证的前提？（例如「用户都想要 X」隐含了「用户知道 X 存在」）
3. **相关 ≠ 因果** — 两个变量同时变化，是因为 A 导致 B，还是因为第三个因素 C？
4. **遗漏的解释** — 有没有其他同样能解释事实的理论？为什么选了这个而不是那个？
5. **失效条件** — 结论在什么情况下成立、什么情况下不成立？边界在哪？

### 使用技巧

- **先拆三层，再逐层攻**。不要一上来就判断「对不对」——先把内容拆成事实/推论/价值判断，事实层核查完了再看推论层。
- **来源要交叉验证**。单一来源永远不够。优先找一手来源（原始数据、官方文档、当事人陈述），其次找多个独立二手来源。
- **样本和时间要看**。「调查显示 80% 的人认为 X」——样本是谁？多大？什么时候做的？代表性够不够？
- **价值判断要显性化**。很多论证的漏洞不在事实层，而在「它预设了什么价值观」。把隐藏的价值判断挑出来，往往比核查事实更有价值。
- **「可以相信到什么程度」是最终输出**。不要给「对」或「错」的二元判断，给置信度 + 适用边界 + 什么情况下会翻转。

## 使用指引：如何选择方法

### 一图对照

| 你的场景 | 用哪个方法 | 一句话判断 |
|---------|-----------|-----------|
| 「这个概念我完全听不懂」 | 双层解释法 | 我连它是什么都不清楚 |
| 「这个成品做得真牛逼，我想模仿学习它」 | 反向拆解 | 我能看出它做得不错，但说不清好在哪 |
| 「我想深度、系统地研究某个东西」 | 横纵分析法 | 我需要知道它的来龙去脉和未来可能 |
| 「这份资料里的说法到底是真的吗？」 | 事实核查 | 我不确定该不该信这个结论/数据 |

### 按需求选方法

- **刚接触新领域** → 先用**双层解释法**建立基础理解
- **看到好的范例想学** → 用**反向拆解**提炼可复用规律
- **要写研究报告/做战略判断** → 用**横纵分析法**做系统研究
- **对某个结论/数据有疑虑** → 用**事实核查**验证可信度

### 组合使用建议

**标准路径（理解 → 模仿 → 深度研究 → 验证）**：
1. 先用**双层解释法**搞懂基础概念（如果涉及陌生术语）
2. 再用**反向拆解**学习具体的优秀实践（如果有一个可参考的范例）
3. 最后用**横纵分析法**做系统性的深度研究（如果需要形成判断和输出报告）
4. 用**事实核查**验证关键结论和数据（在形成判断之后，做最后一道把关）

**反向路径（验证 → 深度研究 → 模仿 → 理解）**：
- 当你对某个结论产生怀疑时，先用**事实核查**定位问题在哪
- 再用**横纵分析法**建立该领域的全局认知
- 然后用**反向拆解**寻找更好的做法
- 最后用**双层解释法**把关键概念吃透

**循环使用**：
- 事实核查中发现「证据不足」→ 换横纵分析法补充研究
- 横纵分析中发现关键概念不懂 → 换双层解释法
- 双层解释中学到了新术语 → 换反向拆解找优秀实践来理解它怎么用
- 四种方法之间可以任意切换，形成「学 → 验证 → 再学」的闭环

## 通用原则

1. **能用自己的话复述 = 真懂了**。复述不出来就是没懂，不要用「好像懂了」安慰自己。
2. **不懂就问，不要硬撑**。四种方法里都设计了「不懂的点」的暴露机制——自检问题、关键选择追问、待确认问题、事实核查的存疑标记，善用它们。
3. **学完一定要用**。解释给别人听、写下来、做个小项目、用到实际工作里——用才是学的终点。
4. **来源要可追溯**。涉及事实性内容，养成标注来源的习惯。今天正确的，明年可能就过时了。
5. **核查是学习的底线，不是可选项**。在形成判断之前，至少对关键事实做一次事实核查——这决定了你的结论是建立在可靠证据上，还是建立在印象上。
