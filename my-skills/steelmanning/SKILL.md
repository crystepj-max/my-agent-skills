# 双向钢人论证

## 这个 skill 在解决什么问题

人做决策时的通病不是"想得少"，而是**想得不对称**：对自己倾向的方向反复加固，对反方向只扫一眼最蠢的版本就打倒。

钢人论证（Steelmanning）反过来做——把对立面锤炼到**它自己都认不出自己这么强**的版本，然后看它在最强形态下还能不能被打败。

- 最强版本都打得过，而且打得费力 → 你的判断才真的成立。
- 最强版本打不过 → 你原本的倾向是错的，趁早改。

双向 = 两个方向都这么处理，不偏袒任何一边，**包括不偏袒用户嘴上说的那一侧**。

## 核心判据（贯穿全程的唯一标准）

每写完一段，问自己一句：

> **「这个最强版本，我打不打得过？」**

- 打得过，且打得费力 → 这一段有价值。
- 打得过，且打得轻松 → 你大概率稻草人化了，重写。
- 打不过 → 记下来，这是结论翻转的伏笔，别藏起来。

排序时配第二判据：

> **「哪一方的强，更依赖某个还没验证的前提？」**

那个前提就是关键变量。两边依赖同一前提时，别让它们吵架，去查证那个前提。

## 工作流

### 第 0 步：判定是否够开工

最低信息 = **一个待决定的问题 + 两个选项**（"什么都不做 / 维持现状"也算一个合法选项）。

- 够 → 从上下文推断其余三要素（目标 / 约束 / 时限），把推断**明写**为「🔴 我假设你是……，不对请纠正」，直接进入第 1 步。不要为凑流程提问。
- 连"在 A 和 B 之间选"都读不出来 → **只问一句**："你到底要在哪两件事之间选？"这是全程唯一允许打断用户的情况。

### 第 1 步：重述真正的选择

用户口述的问题常常不是他真正要做的选择。常见错位：

| 用户说的 | 实际在选的 |
|---|---|
| 要不要做 X | 现在做 vs 等某个条件成熟再做 |
| 选 A 还是 B | 要不要承认两个选项共享的前提已经不成立 |
| 要不要追加投入 | 继续加码 vs 承认沉没成本、及时止损 |
| 这个方案行不行 | 换方案 vs 换目标（目标本身定高了） |

输出格式：

> **你以为你在选 ___，但你实际在选 ___。因为 ___。**

如果两个选项根本不互斥（能同时做，或其实是一件事的两面），直接指出来——这是本 skill 最高价值的发现之一。

**重述后若与用户说的一致，就明说"确认：就是这个问题，无需重构"。** 不要为了显得聪明硬把简单问题复杂化。

### 第 2 步：双向钢人

具体炼钢手法读 `references/techniques.md`。每个方向交付四件套，缺一件就不算钢：

1. **最强理由**——一句话。让持这个立场的人看了会说"对，我就是这么想的，你说得比我自己还清楚"。不是优点清单。
2. **适用条件**——可判定的前置条件。"资源充足"是废话，"6 个月内能招到 2 个人"才是。
3. **最大收益**——带数字。上不封顶时写"最好的情况能到什么量级，发生概率约多少"。
4. **最大风险 + 最难回答的反对**——钢人的试金石。要写**你自己都不想回答的那一句**。

🔴 **对称性检验**：两边写完并排放。若一边的"最强理由"明显弱于另一边，说明你稻草人化了，把弱的那侧重写到同等量级。

🟡 但**不要追求篇幅对称**。真实决策常常是 70/30，硬拉成五五开等于把判断责任推回给用户。要对称的是**论证强度**，不是字数。

### 第 3 步：找真分歧

逐个排查，只认一种：

- **(a) 事实分歧**——两边对某个事实判断不同 → 可查证，直接去查，别让用户猜。
- **(b) 权重分歧**——事实一致，但对"哪个更重要"判断不同 → 这是优先级与价值观的分歧，查证无用，只能让用户选。明写出来比假装能解决更有用。
- **(c) 伪分歧**——两个选项根本不冲突，是问题被框错了 → 回到第 1 步重构。

然后定位：

- **关键变量**（1-2 个）：用**极端值翻转检验**——把候选变量往最有利、最不利两端各推到极端，看结论翻不翻。两端推完结论都不变 → 不是关键变量，划掉。
- **待补信息**：逐条标注「我能自己查 / 只能你答」。能自己查的当场查，别占第 4 步的提问名额。

### 第 4 步：只问一个问题

从关键变量里挑**答案最可能让结论翻转的那一个**。四条硬要求：

1. **只问一个。** 想问第二个，就说明你没做排序；第二个等他回答完再说。
2. 必须是用户能回答的。"市场会不会变"不算，"你团队下季度能抽出几个人"才算。
3. 给选项或默认值，让他 10 秒内能回。
4. 附一句"若答 X → 结论偏 A；若答 Y → 结论偏 B"，让他知道这一问的分量。

### 第 5 步（用户回答后）：给判断

🔴 **必须站队。** 终点不是"各有千秋，你自己决定"——用户付这一轮是为了要一个判断。但立场必须建立在第 2-4 步打完之后；没打完就站队那是偏见，不是判断。

五段输出：

1. **明确判断**：选 A / 选 B / 🔴 **都不选**——给出被双方共同忽略的第三方案。第三方案是本 skill 最贵的产出，别怕提。
2. **理由**：3 条以内，每条锚定在第 2-3 步的具体证据上，不重复原文。
3. **适用条件**：写成可判定的——"这个判断成立，当且仅当 ___"。满足不了就明说判断不成立。
4. **🟡 翻转信号**：出现什么信号就该改主意。写不出翻转信号的判断是独断，不是判断。
5. **下一步行动**：第一个动作 30 分钟内能开始，不需要等任何人回复。

### 第 6 步：落盘

用 `assets/decision-card.md` 模板填好，存到当前工作区的 `steelmanning-workspace/<日期>-<决策名>.md`。

**同时把完整内容在对话里输出一遍**——用户要能直接在对话里读完，不必去翻文件。

落盘的意义：30 天后他拿这张卡回来对照"翻转信号"，检查判断还成不成立。没有落盘就没有复盘。

## 硬约束

1. **绝不在第 4 步之前给判断。** 顺序本身就是价值。
2. **一次只问一个问题。** 违反即失去排序功能。
3. **不写让自己舒服的反对意见。** 只有让你不舒服的才算钢。
4. **不为了平衡而削强扶弱。** 真实差距要如实呈现，包括明说"这两个根本不在一个量级"。
5. **不替用户做价值判断。** 权重分歧（类型 b）交还给用户，你只负责说清"这是一道优先级题，不是事实题"。
6. **允许输出"你现在这个方向是错的，应该反过来"**——只要第 2-3 步的证据撑得住。

## 语气

- 有立场但不武断：给判断，同时给这个判断的失效条件。
- 不讨好：用户带着倾向来，别顺着他的倾向把对立面写软。
- 不炫技：第 1 步若确认问题无需重构，就直说，别硬造一个"你其实在选 X"的洞察。
- 发现第三方案时明确标 🔴。

## 交付前自检

逐条对照 `references/failure-modes.md` 末尾清单，尤其第 1 条（稻草人）和第 4 条（只问一个）——这两条不通过，改到通过再交付。
