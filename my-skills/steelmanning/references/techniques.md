# 炼钢手法库

用途：当第 2 步写不出"最强理由"或"最难回答的反对"时，按手法逐条试。**不要自己现场发明**——下面每一条都经过"是否真的能提升论证强度"的筛选。

---

## 一、怎么找"最强理由"

目标状态：持这个立场的人读后会说"对，我就是这么想的，你说得比我自己还清楚"。

1. **换位法**
   假设你是这个方向的坚定支持者，而且你是个聪明人、有充分的信息。你最想说的第一句是什么？——注意是"聪明人版本"，不是"外行版本"。

2. **最强实践者法**
   这个方向上做得最成功的那个人，他会怎么论证？不要找做得最差的那个当靶子。

3. **剥离情绪词**
   把"风险很大"换成具体机制与数字。情绪词一出现，论证强度立刻掉一档。
   - 弱：`这个方案风险很大`
   - 强：`这个方案把 70% 的交付压力压在最后 3 周，任何一个环节延期 5 天都会导致整体上线推迟一个月`

4. **时间旅行法**
   假设这个方向已经成功了，回看当初最关键的那一步是什么——那通常就是最强理由的核心。

5. **检测**
   写完后读一遍。如果持这个立场的人会说"你歪曲了我的意思"，重写。

---

## 二、怎么找"最难回答的反对"

目标状态：这句话让你自己写的时候都觉得不舒服。

1. **经典失败案例归因**
   找这个方向最著名的失败案例，问一句：它失败是因为**执行差**，还是因为**方向本身有硬伤**？
   - 执行差 → 不是有效反对，换一个。
   - 方向有硬伤 → 这就是最难回答的反对。

2. **反向时间旅行**
   假设这个方向已经失败了，回看最致命的那一步是什么。把它写成一句陈述。

3. **最尖锐批评者法**
   这个方向上最有名的反对者，他最强的一击是什么？不是他重复最多的那句，是**最让你答不上来的那句**。

4. **一句话沉默测试**
   自问："如果我要让这个方向的支持者当场语塞，只允许我说一句，我说什么？"

5. **检测**
   这句话让你自己觉得不舒服吗？不觉得 → 不够钢，继续挖。
   如果你能立刻想到怎么反驳它 → 太软了，继续挖。

## 三、怎么找"真分歧"

三步检验，按顺序走：

**第一步：剥离事实**
问：如果两边共享同一个事实认定，还会吵吗？
- 不吵了 → **(a) 事实分歧**。去查证，别让用户猜。
- 还是吵 → **(b) 权重分歧**。交还给用户，明说"这是一道优先级题，不是事实题"。

**第二步：检验互斥性**
问：这两个选项能同时做吗？
- 能 → **(c) 伪分歧**。问题被框错了，回到第 1 步重构。

**第三步：绕过选项**
问：如果 A 和 B 都不可选，用户真正想要的结果是什么？
- 答案常常就是**第三方案**。这是本 skill 最贵的产出，找到就标 🔴。

## 四、关键变量的极端值翻转检验

操作：

1. 列 3-5 个候选变量。
2. 每个变量往**最有利**方向推到极端：结论变了吗？
3. 再往**最不利**方向推到极端：结论变了吗？
4. 判定：
   - 两端推完结论都不变 → **划掉**，它不影响决策，别浪费资源。
   - 只有一端会变 → 记为"单向关键"，值得留意但不优先。
   - 两端都能翻转 → **核心变量**，单独查证、优先提问。

例：纠结"要不要招人扩张"
- 候选变量：下季度营收增速 / 招到人所需周期 / 现有团队满负荷程度
- 营收增速推到极端（涨 3 倍 / 跌一半）→ 结论变了 → 关键
- 招人周期推到极端（1 周 / 6 个月）→ 结论也变 → 关键
- 现有团队满负荷程度（50% / 100%）→ 结论不变 → 划掉

## 五、第三方案的三个来源

当两边钢人都打完、发现谁都打不过谁时，别急着让用户二选一，先找第三方案：

1. **时序拆解**
   不是"A 或 B"，而是"**先做 A 的一部分，满足条件再做 B**"。
   例：不是"自建还是外包"，而是"先外包跑通流程，量过 5000 单后自建"。

2. **范围拆解**
   不是"全做或不做"，而是"**在 X 场景做 A，在 Y 场景做 B**"。
   例：不是"会员制还是按次付费"，而是"高频用户走会员，低频用户走按次"。

3. **前提拆解**
   两个选项依赖的某个**共同前提**，如果这个前提能被打破，问题就消失了。
   例：两个方案都假设"用户只会在 App 内转化"，那么真正该验证的是"能不能在微信里直接转化"——这才是第三方案。
