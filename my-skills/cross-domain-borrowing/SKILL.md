# 跨领域借解（Cross-domain Borrowing）

## 这是什么

用户带着一个在本行业里反复卡住、常规做法都失灵的问题来找你。本 skill 不做行业内的横向对比（"竞品怎么做"），而是把问题**剥掉术语抽象成结构**，去**结构同构但表象完全不同**的领域里找已经跑通的解决机制，再翻译回来。

为什么管用：一个领域里的"常识难题"，往往在另一个领域里已经被解决了几十年，只是两边用的词不一样。本行业的人看不见，是因为术语把结构盖住了。

## 触发与排除

**应触发：**
- 用户明确说"跨领域""别的行业怎么解决""类比一下""跳出本行业看看"
- 用户描述一个反复卡住的问题，并说"常规做法都试过了""不管用""想换个思路"
- 用户怀疑自己所在行业的"标准答案"本身有问题

**不触发：**
- 纯信息检索、纯执行任务
- 问题其实缺的是执行资源而非思路 —— 这时直说：你缺的不是新解法，是人和预算。硬凑跨领域方案是浪费时间。

## 硬性规则

1. **抽象不到位不往下走。** 结构没抽象好就去找案例，找到的一定是"包装相似、机制不同"的假类比。宁可多在抽象上花时间。
2. **类比是假设生成器，不是验证器。** 每个借来的方案都必须是"待验证假设"，配一个能证伪它的动作。跳过这步，就是把别人的成功故事当成自己的答案——这是本 skill 最容易犯、后果最严重的错误。
3. **3 个领域必须真的远。** 凑不满就直说"我只找到 N 个真正同构的领域"，不用近亲领域充数。
4. **不编造案例。** 每个案例标可信度（高/中/低）+ 一句核查线索。拿不准的细节写"大致是…（待核）"，不要写死。

## 第一步：信息核查

判断四项是否齐备：
- **背景**：事情发生在什么场景，牵涉谁
- **当前做法**：现在是怎么应对的
- **现实约束**：时间、预算、人力、权限、合规、关系——哪些不可谈判
- **具体卡点**：到底卡在哪一步，卡了多久

缺项且影响方向时，**一次问完**，不要挤牙膏。信息基本齐备就跳过，直接开工。

缺项但**不影响推导主干**时（例如用户身份、最终用途可合理推断），不要为了确认而打断——基于假设继续，并在第 1 步输出结果里显式标出「以下基于假设：…」。不要把推测伪装成已知条件。

## 工作流程

### 第 1 步：剥术语，抽象成底层结构

把所有行业术语换成"谁对谁做了什么、想要什么、被什么挡住"的通用描述。用五元组逼出结构：

> **谁**（行动方）/ **想要什么**（目标）/ **稀缺或被约束的是什么** / **卡在哪**（谁的行为或什么机制挡住）/ **为什么常规补法补不上**

**中距抽象检验**（这步决定后面找到的是真类比还是假类比）：
- 抽象太低：描述里还留着原领域专有名词（"转化率""复购""排班"），换个领域就读不通 → 再往上提一层
- 抽象太高："资源有限""信息不对称""人不配合" → 全世界都符合，没有区分力 → 往下降一层
- **合格线**：拿这个描述去问——"它在 3 个完全不相关的领域里都说得通吗？在每个领域里都能指出具体的行动方和卡点吗？"都能 → 抽象到位

给结构起个名字。命名卡住时查 `references/structure-archetypes.md`（18 个常见结构原型）——它只是词表和搜索起点，不要把原型自带的解法直接当答案。

### 第 2 步：命名核心矛盾，诊断常规解法为何失效

**核心矛盾**必须写成这个句式，逼出真矛盾而非伪矛盾：

> 为了 **[目标 A]**，必须 **[动作 X]**；但 [X] 会 **[削弱 B]**，而 B 同样是必需的。二者无法同时最大化，因为 **[结构性原因]**。

**常规解法失效的原因**，从这四类里认领（可不止一条），并给出证据：
1. **层级错配** —— 在症状层打补丁，没动产生症状的结构
2. **代理指标** —— 优化的是可测量的替代物，不是真目标
3. **反馈方向错误或延迟** —— 努力和结果之间隔太久或方向相反，导致过冲、振荡或不作为
4. **只加资源不改结构** —— 往同一个漏斗里灌更多投入，漏斗形状没变

### 第 3 步：跨领域搜索（历史案例 + 至少 3 个远距离领域）

**距离检验**（三条都要过）：
1. 三个领域必须落在 `references/domain-map.md` 的**三个不同大类**里
2. 两个领域之间不能有明显的知识谱系或供应链关系（制造业↔物流↔供应链 属近亲，只能算一个）
3. 找的是**机制同构**，不是**故事相似** —— "看起来像"不算数，要能说清两边的作用链条是同一条

**降权清单**（不是不能用，但用了必须说清"机制到底是什么"，说不清就换）：
- 丰田精益 / 看板 —— 除非问题真的是在制品排队与瓶颈
- 蚁群、蜂群、进化论等生物隐喻 —— 包装相似，机制难落地
- 孙子兵法 —— 太泛，不是机制
- 某大厂做法，若其成立前提其实是"有钱、有数据、有垄断地位" —— 那不是可迁移机制

**搜索技巧**：拿第 1 步的**结构描述**去匹配，不要拿原领域的名词去匹配（搜"库存周转"只会找到别的库存问题）。优先找"被这个问题折磨了很多年、最后不得不想出办法"的领域——经过实战打磨的机制含金量最高。

### 第 4 步：逐案例分析（每个案例 7 项）

1. **那个领域遇到了什么问题** —— 先用它的术语说，再翻回通用结构
2. **用了什么解决机制** —— 写机制，不写做法。机制格式：`当 [结构条件] 成立时，通过 [作用方式]，把 [矛盾的一方] 变成 [可被管理 / 被交易 / 被延迟 / 被分散的变量]`。只写"他们做了 X"不够——做法不可迁移，机制才可迁移
3. **与你的问题相似在哪** —— 具体指出作用链条的哪个环节同构
4. **哪些部分可以迁移** —— 拆成"可直接搬 / 需改造 / 搬不了"三档
5. **什么条件下会失效** —— 边界条件，越具体越好
6. **结构差异清单** —— 源领域有、但你这边没有的条件，逐条列。**只列相同点不列差异，是类比推理最常见的翻车方式**
7. **可信度 高/中/低 + 一句核查线索**（如"可查：美国器官共享网络 UNOS 的分配规则变迁"）

**优先找失败案例**：某领域试过类似机制却失败了，信息量常比成功案例更大——它直接告诉你第 5 项的失效条件。

### 第 5 步：挑 3 种机制 → 翻译 → 一个低成本可逆实验

挑 3 种（机制重复的合并），每种按五段翻译：

> **机制：[名字]（来自 [领域]）**
> - **翻译成你的处境**：具体怎么做，谁来做，动到什么
> - **成本**：时间 / 人力 / 钱 / 政治成本（需要谁点头、可能得罪谁）
> - **收益**：解决核心矛盾的哪一侧，代价是让哪一侧变差
> - **风险**：最可能怎么失败，早期预警信号是什么
> - **迁移保真度 高/中/低**：源领域与你处境的结构差异有多大（回看第 4 步第 6 项）

最后**只推荐一个先试的实验**，必须写清：
- **做什么**：一个具体动作
- **多长 / 多大**：几人几天、花多少钱
- **验证哪个假设**：它如果成功，证明第 2 步诊断的哪一条成立
- **事先定好判定线**：什么结果算"信号成立"，什么算"证伪"。**判定线必须在动手前写死**——事后定线等于没定
- **怎么可逆**：退回去的动作是什么，退路代价多大
- **如果证伪**：下一步去看剩下两种机制里的哪一个

## 输出模板

严格沿用下列小标题。

```

> 谁 / 想要什么 / 稀缺什么 / 卡在哪 / 为什么补不上
**结构名**：…
**抽象检验**：为什么这个层级不高不低

## 二、核心矛盾

（历史案例 + ≥3 个远距离领域）

## 四、逐案例拆解

1. 那个领域的问题：
2. 解决机制：当 […] 时，通过 […]，把 […] 变成 […]
3. 相似在哪：
4. 可迁移部分：可直接搬 / 需改造 / 搬不了
5. 失效条件：
6. 结构差异（源领域有你没有的）：
7. 核查线索：

## 五、最值得借的 3 种机制
（每种按 翻译 / 成本 / 收益 / 风险 / 迁移保真度 五段写）

## 六、先试这个
做什么 / 多大多长 / 验证哪个假设 / 判定线（事先写死） / 怎么可逆 / 证伪后看哪个

## 七、提醒
以上三个方案目前都是**待验证假设**，不是答案。最高杠杆的核实项是：[…]，要我现在查证吗？
```

## 红线

- **不许把"某领域这样做成功了"写成"你也该这样做"。** 借来的是假设，不是结论。
- **不编造案例。** 拿不准就标低可信度并给核查线索；查不到就说查不到。
- **找不到同构就直说。** 硬凑三个领域，比只给两个真同构的更糟。
- **不把"有钱 / 有数据 / 有垄断地位"当机制。** 那叫资源，不叫方法。
- **不用生物或军事隐喻做装饰。** "像免疫系统一样"这类话必须落到具体机制，落不到就删掉。
- **也要准备好说"你的常规解法其实是对的"。** 如果跨领域看下来确实没有更好的机制，直说，并用结构证据证明。硬推翻反而是失职。
- **翻译要落地。** 每个方案必须能回答"明天谁去做、做什么"，停留在"可以借鉴 XX 思想"的输出是废话。
- 输出语言跟随用户提问语言。
