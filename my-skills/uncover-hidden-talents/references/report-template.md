# 《个人天赋使用说明书》撰写规范

目标篇幅：**约一万字**。写入 `天赋档案/个人天赋使用说明书.md`。

## 三条贯穿全文的硬要求

1. **每个判断都要挂经历链。** 每个天赋后面，都必须能追溯到用户在访谈中讲过的具体经历，并**引用他自己的原话**。没有经历链的天赋，不许写进报告。
2. **不能只写好的。** 阴影面、高消耗区、现实限制、失效环境，必须写，且用力程度和优势部分相当。一份只讲好话的说明书是废纸——用户看完会更迷茫，因为他知道生活不是那样。
3. **实验必须具体到能直接去做。** 「多尝试新事物」不算。「周三晚上两小时，把你在 XX 上的想法做成一个最小版本，发给三个人看」才算。

## 语气

像一个真正看懂了他的朋友，在认真地跟他说事。温暖，但不煽情；直接，但不冷。可以用一点幽默。禁止励志口号、禁止鸡汤、禁止「你一定可以的」。

用户是来看懂自己的，不是来被鼓励的。**告诉他真相，比让他舒服更重要——但真相要说得有温度。**

---

## 报告结构

结构可依据用户实际情况自由组织，但以下八块必须全部覆盖。括号内为建议字数。

### 一、序章：这不是一份测评报告（约 500 字）

明确告诉用户这份文档的边界：
- 它不是测评结果，不是给你贴标签，不预测你的未来。
- 它的全部依据，是你自己讲出来的经历——所以它可信，也所以它可能不全。
- 它是一份「使用说明」，讲的是怎么用，不是「鉴定书」。
- 结尾回扣那句核心的话：**天赋永远不会过期。**

### 二、你的天赋地图：总览（约 600 字）

先用一页纸把结论摆出来，让人一眼看到全貌：

- 3–5 项底层天赋，每项一句话定义（用大白话，不要术语）
- 一个总览表格：天赋名称 / 一句话定义 / 证据强度（强 / 中 / 待验证）/ 首次出现的年龄

**证据强度必须诚实标注。** 出现 3 次以上独立经历 = 强；2 次 = 中；1 次 = 待验证。不要为了让报告好看而全部标「强」。

### 三、天赋详解：每一项及其经历链（约 1200–1500 字 × 3–5 项）

这是报告的主体，篇幅占比最大。每一项天赋按以下四段写：

**1) 这个天赋是什么**
用大白话定义，不要用术语。说清楚它是「做什么事的能力」，而不是某种性格形容词。

**2) 它的经历链**
按时间顺序列出支撑这个判断的经历，每条包含：
- 时间（几岁 / 哪个阶段）
- 具体事件（用户讲的原话或细节）
- 这件事说明了什么

**必须引用用户原话**。他自己的话比任何分析都有说服力，也是让报告「不像 AI 写的」的关键。

**3) 它为什么一直没被你当成天赋**
解释这个天赋的自我隐形机制。常见原因：
- 太容易了，以为别人也一样
- 被当成缺点批评过
- 没有对应的职业名字，所以不被认可
- 它出现在「不正经」的场景里（玩游戏、闲聊、帮忙），所以不被计入

**4) 它在哪些地方能变现**
具体到场景，不是「可以做咨询」这种空话。要说清楚：什么样的岗位、什么样的项目、什么样的合作关系，能让这个天赋变成价值。

### 四、阴影面：你的天赋曾经被误解成什么（约 1500 字）

**这是全文最见功力的部分，也是最能打动用户的部分。**

对每一项主要天赋，写出：
- 它在压力、错误环境或过度使用时，长什么样（比如：对细节的敏感 → 在混乱环境中变成控制狂；对人的敏锐 → 在缺乏安全感时变成过度揣测）
- 它从小被谁、用什么话批评过（引用用户讲过的原话）
- 那个批评为什么是错的——不是批评者坏，而是那个特质放错了地方
- 这个误解让你付出了什么代价（压抑它、假装它没有、为此内疚）

写作要求：**要敢写，要写得具体，不要轻描淡写。** 用户如果在这里没有被说中，整份报告的可信度都会打折。

### 五、你的能量地图（约 1200 字）

四类区域，每类下列出具体的事（用用户访谈中提到的）：

| 区域 | 定义 | 写作要点 |
| --- | --- | --- |
| **天赋区**（做得好 + 回血） | 核心资产 | 说明该主动争取什么 |
| **待开发区**（做得一般 + 回血） | 潜力最大，最容易被忽略 | 说明为什么值得投入——能力可以练，驱动练不出来 |
| **高消耗区**（做得好 + 抽干） | 被训练出来的能力，不是天赋 | **明确说清「这不代表你要立刻辞职」**，给出渐进策略：如何减少比例、如何改变做法降低消耗 |
| **止损区**（做得一般 + 抽干） | 应尽量减少 | 给出替代方案或委托/协作建议 |

能量地图部分要给一句总判断：比如「你的能量主要消耗在 X 上，而它恰恰是你最不缺外部认可的地方——这意味着你有空间把它交出去。」

### 六、环境适配：天赋在哪里发光，在哪里熄灭（约 1000 字）

分两块，每块都举具体场景（公司类型、团队规模、管理方式、任务性质、节奏）：

**容易发挥的环境**
- 什么样的任务结构（模糊 vs 清晰、长期 vs 短平快）
- 什么样的团队与上级
- 什么样的工作节奏与反馈周期

**容易失效的环境**
- 什么样的环境会让你的天赋变成负担
- 哪些信号出现时，说明你已经在不适配的环境里了（**要写出可识别的早期预警信号**，比如「你开始频繁做 X」「你周日的晚上开始不舒服」）

这一块的判断依据同样来自用户访谈中提到的「我不像我自己」的时刻。

### 七、怎么用：工作方式、合作方式、职业方向与现实限制（约 1500 字）

**工作方式**
- 适合的任务切分方式、时间块安排、反馈频率
- 如何安排一天，让天赋区占主要位置

**合作方式**
- 需要什么样的搭档来补位（基于你的高消耗区反推）
- 在团队里最适合承担什么角色
- 与什么类型的人合作会互相消耗

**职业方向**
- 2–3 个具体方向，每个说明：为什么匹配（挂到前面的天赋）、现实路径、需要补什么

**现实限制（必须写，不许跳过）**
- 年龄、家庭责任、经济压力、已有沉没成本、行业周期、地理位置
- 明确说出哪些方向在当下**不可行**，以及为什么
- 给出在限制条件下的次优解

**这一节的价值在于诚实。** 一份不考虑现实限制的天赋报告，是精神上的奢侈品，看完只会更焦虑。

### 八、接下来 30 天：低成本实验清单（约 1200 字）

**这是报告唯一要求用户立刻行动的部分，必须极其具体。**

给 3–5 个实验，每个实验包含：

```markdown
### 实验 N：[一句话名字]

- **做什么**：具体到能直接执行的动作
- **什么时候**：具体到周几、大概几小时
- **成本**：时间 / 金钱 / 人情
- **验证什么**：这个实验是为了确认或推翻哪条判断
- **怎么判断成功**：可观察的结果（不是「感觉不错」，而是「做完之后你有没有想继续」「你有没有忘记时间」）
- **失败意味着什么**：如果做完毫无感觉，说明什么，下一步怎么办
```

**实验设计原则：**
- 低成本、可逆、一周内能跑完
- **优先选「待开发区」的事**——能力可以练，但驱动练不出来，待开发区的验证价值最高
- 至少有一个实验直接冲着「嫉妒与渴望」那条主线，验证你以为想要的是不是真的想要
- 每个实验都要写清楚「失败意味着什么」。不敢写失败标准的实验，不是实验，是许愿。

### 九、尾声（约 400 字）

收束全文。要点：
- 这份说明书会随经历更新，它不是终稿
- 天赋不会过期，但它需要被放到对的地方才会显现
- 一句基于他具体情况的话（不要用通用金句，要针对他访谈里最触动你的那个细节）

## 写作检查清单

完成后逐条自检：

- [ ] 每个天赋判断都能追溯到具体经历，并引用了用户原话？
- [ ] 证据强度标注诚实（有没有把「待验证」写成「强」）？
- [ ] 阴影面写得够具体、够用力？有没有回避那些难写的地方？
- [ ] 高消耗区单独列出了，没有混进天赋清单？
- [ ] 现实限制写了？有没有说哪些方向当下不可行？
- [ ] 30 天实验具体到能直接执行？每个都有失败标准？
- [ ] 全文没有励志口号和空泛赞美？
- [ ] 篇幅接近一万字？

任何一条没过，改完再交付。
