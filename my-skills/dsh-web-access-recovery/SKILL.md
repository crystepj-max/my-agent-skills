# DSH 网页端访问恢复

## 先确认用户要访问的实例

从用户当前链接、项目/服务配置、当前监听端口、进程启动参数及可用 DSH CLI 核对目标实例。旧端口、目录名、产品/开发映射和启动器仅为历史线索，不以名字或端口猜测归属；若存在多个可能目标，先用只读信息消歧。

对目标实例检查 TCP 监听、HTTP 响应、浏览器认证状态和限定范围的启动日志。HTTP 401 可能是认证流程的一环，不一定表示进程故障；curl 的 000 也可能是请求错误或代理问题，须另行检查监听状态。访问本机回环地址时若怀疑代理干扰，可为该次请求明确绕过代理。具体状态码的含义应结合当前 DSH 版本源码/配置确认。

## 使用当前启动器或 CLI 提供的状态

若当前项目确实提供服务状态命令，先阅读其当前帮助和项目说明，再查询目标实例；不能假定 scripts/dev-plugin.mjs 或 npm run dev:plugin 存在于本任务仓库。状态命令给出的 URL 可能不含认证信息，结合该版本当前认证流程确认后再给出结论。若服务当前已有可用登录方式，优先恢复访问，不因历史经验自动重启。

## 获取用户所需的登录方式

如果用户是在恢复自己目标实例的访问，先查当前 DSH 版本公开支持的认证方式与目标实例可用的登录 URL。只读取该实例服务配置指定的日志，或本轮启动命令对应的终端输出；不能用 /tmp/*.log 全量搜索或凭旧文件名猜测。若项目公开提供 CLI/API，就按其当前帮助使用；不要杜撰 token 获取命令。

launch token、cookie 与含认证参数的 URL 都是凭据。仅为判断目标实例或恢复用户访问所必需时使用，不将其写入日志、报告、记忆或无关输出。用户明确请求恢复访问时，可把该目标当前有效链接交给用户，或在用户授权的浏览器中打开；不要附带原始日志或凭据值。cookie 有效期、端口绑定和重启后失效行为都要查当前实现，不以旧的 30 天或“必然作废”规则代替证据。

## 端口与认证线索

同一实例的认证是否绑定主机/端口、运行实例是否随机选端口，按当前版本源码与服务配置确认。历史端口与旧日志不得作为当前依据。不能为找认证链接扫描整个临时目录；只看所选实例被配置的日志路径或本轮终端输出，并在向用户展示前避免输出日志中的其他敏感字段。

## 判断本会话的服务运行能力

启动、后台运行及进程保留行为取决于当前宿主工具、会话和权限。先按本会话实际工具能力及目标项目说明探测；不要假定 run_in_background 一定失败或常驻，也不要因某工具名或猜测的沙箱限制让普通恢复请求提前停止。若确实缺少所需权限，说明准确缺少的操作与可行替代。

## 重启前核对用户进度

检查所选实例的活动会话、临时注入插件和未保存工作流状态。只有当前证据表明重启会造成用户尚未接受的进度损失时，才对该具体损失询问；已有重启授权可复用，不能因进入排障步骤而重复申请。优先尝试当前认证实现支持的无损访问恢复方式。

## 诊断服务启动失败

按当前实例服务管理器读取真实状态，并只检查该实例配置的日志与启动参数。若有 NODE_MODULE_VERSION 或原生模块加载错误，核对运行时实际版本、项目声明和该模块 ABI；Node 22/24、ABI 127/137 及 fs-ext 仅是历史案例，不是当前环境结论。确有版本错配时，根据当前项目支持的启动配置修复，修改系统启动器或 launchd 配置前遵循用户授权范围与项目政策。

launchd、后台执行或 GUI 会话操作是否可用，先在当前宿主探测能力与权限。不能把旧会话里的 Bootstrap failed 或某个 shell 的限制说成必然失败。

## 锁文件超时

仅当当前目标明确报告某个锁文件超时，才定位该确切锁及其格式/实现，再核对可能的所有者与写入活动。不能仅因 lsof 没有结果、某 PID 不存在或历史源码把锁称作“操作员恢复”，就推定它是孤儿。未知持有者、无 owner 信息、锁路径超出目标或无法证明安全时保留原状并说明阻塞；不得删除其他实例或整目录的锁。遇到 unlink/权限错误时，根据当前实现与实际返回排查，不跳过系统保护。

## 按当前工具启动服务

使用当前项目记录的正式启动方式和本会话提供的进程工具。不要假定前台命令超时后会自动后台化，也不要假定后台任务会被清理或永久保留。若本轮为诊断启动了临时探针，记录它的精确 PID、启动参数、日志路径和新建产物；检查完成后只停止仍与该记录匹配的临时探针，并只清理本轮新建且确认可丢弃的文件。用户要恢复的目标常驻服务不是临时探针；按用户目标启动或重启后应保持运行。不得使用 pkill -f 宽匹配清理。

## 当前版本证据与操作边界

如果 HTTP 状态含义、token 来源或启动方式影响判断，检查当前安装版本对应的源码和公开 CLI 帮助；旧路径如 packages/client/connection/src/browser-auth.ts 仅供搜索线索，须先确认文件存在并找到实际认证处理逻辑。端口、profile、LAN PIN 和不同启动运行时都从当前配置/进程获得后再陈述。

诊断与读取目标实例状态以只读为主。修改系统启动器、服务 plist、认证配置或插件配置时，核对当前任务是否已明确覆盖该文件和影响；不把“恢复访问”自动扩成对其他实例的改动。已授权的重启无需重复询问。只有发现会损失用户此前未接受的活动进度或新增目标范围，才就该变化询问。访问链接中的 launch token/cookie 不输出到原始日志、报告、记忆、进程参数或无关窗口；用户明确需要恢复本人目标实例访问时，可安全交付该实例当前有效的链接。
