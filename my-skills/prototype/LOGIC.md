# Logic Prototype

用单文件、可操作的 HTML 演示回答有关业务规则、状态转换或数据形状的问题。演示让使用者亲自触发操作并观察状态变化；界面使用业务语言。分支、提交、评审三态和正式实施统一遵守 [SKILL.md](SKILL.md)。

## 适用情形

- “先发生 X 再发生 Y 时，状态应该怎样变化？”
- “这个数据结构能否表达……？”
- “我想先操作几种情况，再定 API 或业务规则。”

若核心问题是界面结构和视觉层级，使用 [UI.md](UI.md)；若两者都会影响结论，可同时制作 UI 变体和逻辑演示。

## 制作演示

1. 在页面顶部用一段可见的说明写清问题、假设和要验证的规则。原型分支、目录和运行约定按主文件执行。
2. 在一个 `<script>` 中实现小型纯逻辑模块，例如 reducer、状态机或纯函数。模块不读取 DOM、不处理点击、不访问网络或存储；页面通过调用模块来呈现结果。
3. 把演示做成单个内嵌 HTML/CSS/JavaScript 文件，无框架、打包器或服务器依赖。交付路径和双击打开方式；若受本机浏览器策略限制，写明替代运行方式和限制。
4. 页面需显示：
   - 当前完整相关状态，使用带标签的业务字段，而非只显示原始 JSON；
   - 刚执行的操作、结果以及拒绝操作的原因，使成功和失败都能看见；
   - 可自由点击的操作按钮，便于测试任意顺序和边界；
   - 可重复运行的引导场景。每个场景说明起始情形和观察点；每一步都是按钮，点击后执行一步并显示进度；重新开始会还原到固定初始状态。
5. 至少覆盖一条正常路径、一条边界路径和一次非法操作尝试。非法操作可由使用者触发，以观察模型是拒绝、忽略还是改变状态；演示要明确呈现实际结果。保持界面简洁，避免动画和装饰干扰判断。
6. 默认只用内存数据。用户授权且问题确需验证时可读取真实数据；写操作、网络变更和外部副作用默认模拟或使用隔离资源，并在页面或说明中标明。

## 运行和评审

按主文件要求启动或打开 HTML，实际执行每个引导场景和关键自由操作。记录浏览器/运行方式、操作步骤、观察到的状态和失败原因。只检查 HTML/JavaScript 或逻辑源代码时，标为静态检查；没有实际打开并交互时标为“待运行验证”。不要把代码检查当成交互通过。

将 HTML、运行说明和设计记录定向提交到 `codex/prototype-*` 分支；只包括本次原型所需内容。评审时给出原型 `branch@commit`、正在验证的问题、观察结果、仍未知项和拟实施范围，并标明“用户结论：待确认”直到收到回复。请用户明确选择：

- **通过并进入实施**：用户用自然语言明确认可该版本并要求按所选规则和范围实施即可，无需固定口令；随后才在独立的 `codex/implement-*` 分支实现并进行项目检查。
- **退回**：按反馈修改演示，重新提交受影响的版本、实际运行相应场景，再次确认。
- **暂缓**：记录用户结论并保留原型分支和提交；不进入实施。

静态检查通过、模型推荐、沉默或“看起来对”等含糊反馈不等于通过。每次收到用户结论后，在原型分支的设计记录中追加日期、用户原意、结论（通过 / 退回 / 暂缓）、选定规则和范围，以及被用户审阅的精确 `branch@commit SHA`，并做一个独立的本地归档提交。归档提交引用先前审阅的原型 SHA，不写自身 SHA；提交受阻时明确报告归档未完成。实质改动后对新版本重新确认。通过并进入实施时，须先完成确认归档，再从正式基线创建独立实施分支；交付链接原型产物 SHA 和确认归档 commit。后续实现可抽取已验证且确认的纯逻辑，按项目结构重新落实和验证；不得整支合入原型分支，也不得把演示 HTML 壳带入产品。原型和实现的追溯关系保留，用户明确要求清理前不自动删除。

## 避免

- 让纯逻辑模块依赖 DOM、事件处理器、网络或持久化。
- 只显示 JSON，或执行操作后不显示状态差异、拒绝原因和引导步骤进度。
- 让原型写入真实业务数据，或把演示 HTML 壳当成正式页面。
- 用静态代码检查声称用户已经实际操作或接受了原型。
