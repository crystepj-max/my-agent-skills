# Prototype

原型交付包括可运行产物、它回答的问题、备选方案、运行说明、观察证据和仍未知的部分。原型用于获得设计结论；正式实现是后续独立阶段。

## 选择问题和形态

从用户请求、当前项目和相关代码中判断问题：

- 视觉或交互问题：使用 [UI.md](UI.md)，提供布局、信息层级或主要操作有实质差异的可切换变体。
- 业务逻辑、状态或数据形状问题：使用 [LOGIC.md](LOGIC.md)，制作单文件、可操作的 HTML 演示。
- 问题同时涉及界面选择和状态行为时，组合两种形态；共用同一原型分支、说明和确认记录。

目标已清楚就直接开始；仅当不同理解会导致完全不同的原型时才询问。上下文足以选择但仍有假设时，记录假设并继续。

## 原型分支、归档与运行

1. 先读取项目约定并确认正式基线。为原型从该基线创建独立的 `codex/prototype-<topic>` 分支。共享工作区存在无关改动或并行写入时，使用独立 worktree 隔离；不要把未审阅改动带入原型。若无法创建所需隔离环境，说明实际阻塞，不在混合工作区冒充已归档。
2. 只放入回答问题所需的原型、运行说明和设计记录。记录问题、方案、被比较的差异、观察证据和未知项；标明 `PROTOTYPE`。单文件 HTML 要能直接打开；没有 Git 项目时，可在专用临时目录建立独立临时仓库，不要初始化无关业务目录。
3. 默认使用内存状态。经授权可读取适合的真实数据；写入、网络变更和其他外部副作用默认使用模拟或隔离资源。说明数据来源和副作用边界。
4. 只实现回答问题必需的路径和状态，少做抽象；不默认增加生产测试套件、完整错误恢复或长期架构。仍须实际运行原型并操作关键正反场景，记录环境、运行方式和观察结果。只做静态检查时，明确标为“待运行验证”；不得把静态检查说成交互通过。
5. 将本轮原型、运行说明和设计记录定向提交到原型分支，提交中不混入无关改动。此本地原型提交用于留证；推送、PR、安装或外部发布仍按用户授权和项目约定处理。评审交付时报告完整 `branch@commit SHA`，用它绑定后续结论；不要要求原型提交在自身内容中包含自己的 SHA。

## 原型确认与正式实施

交付评审时，明确列出原型 `branch@commit`、备选方案、推荐项、拟实施范围、运行证据和未知项。尚未收到用户结论时明确写“用户结论：待确认”，并请用户明确选择：

- **通过并进入实施**：用户用自然语言明确表示认可该原型并要求按所选方案和范围进入实施，即为确认；不要求固定口令。之后继续实施，不重复索取同范围许可。
- **退回**：继续修改原型、更新提交并重新运行受影响场景，然后对新版本重新确认。
- **暂缓**：记录结论并保留原型分支和提交；不进入实施。

技术检查通过、助手推荐、沉默或单独的“喜欢 B”等未说明是否进入实施的反馈，都不构成实施确认。每次收到用户结论后，在原型分支的设计记录中追加确认归档，记录日期、用户原意（保留原话或忠实转述）、结论（通过 / 退回 / 暂缓）、所选方案、实施范围及用户实际审阅的原型 `branch@commit SHA`；再做一个独立的本地归档提交。归档提交引用先前审阅的原型 SHA，不引用自身 SHA。若用户退回，修改原型并更新提交、复核受影响场景，再对新版本重新确认；若暂缓，保留原型和归档记录，不进入实施。若归档提交受阻，明确报告归档未完成，不声称追溯闭环。若确认后原型、方案或范围发生实质变化，先对新版本重新确认。保留原型、确认归档和正式实现之间的追溯信息；不自动删除分支或产物，只有用户明确要求弃用或清理时才处理本轮内容。

用户明确表示“通过并进入实施”，且确认归档已提交后：

1. 从正式项目基线创建独立的 `codex/implement-<topic>` 分支。
2. 按已确认范围在该分支实现所选方案并运行项目适用的检查。原型分支只作参考，不能整支合入正式基线；移除原型路由、变体切换器和演示壳。已验证且被确认的纯逻辑可抽取并按正式项目结构实现、验证。
3. 在正式实施交付中链接用户审阅的原型 `branch@commit SHA`、独立的确认归档 `branch@commit SHA`、用户确认的方案与范围、实施分支、检查结果及尚未验证事项。若归档提交受阻，报告该缺口，不声称完成正式交付。

## 完成条件

交付原型路径和运行方式、原型 `branch@commit`、问题与方案、实际观察证据、未知项，以及当前确认状态（未回复时为“待确认”，收到结论后记录“通过 / 退回 / 暂缓”及用户原意、日期、方案、范围和对应原型 SHA）。用户结论写入原型分支的设计记录并以后续本地提交归档；报告该归档提交。进入实施时，另行交付正式实施分支，并链接原型产物版本、确认归档和项目检查结果。完成不要求自动推送、发布、安装或清理原型。
