# 故障调查与修复

1. 明确用户实际遇到的症状，读取相关代码、已有日志和已知版本差异；保护凭据，只呈现必要证据。
2. 优先建立能捕捉该症状的验证方式。允许只读调查和标明待验证的解释帮助构造复现；运行速度是优化目标，不是开工门槛。偶发问题记录触发频率，不声称一次未出现就已修复。
3. 围绕证据提出可证伪解释，一次改变一个相关因素。不机械凑满假设数量或反复优化调查工具。
4. 修正前记录故障证据，修正后重跑同一场景及必要回归。证据不足时如实保留未验证状态，不用无关检查顶替。
5. 缺环境时先完成可用资料分析和可逆准备，只对无法自行解决的关键缺口提问，并继续其他部分。
6. 移除本轮临时调查改动，说明结论和验证边界；发现无关架构问题只记录，不自动开启另一轮改造。

第三方方法保留于 `~/.local/share/agent-skills/references/diagnosing-bugs/`，用于选择调查方法，不继承其“复现前禁止调查”等流程限制。
