# Fact Check（事实核查）

把用户丢来的一则说法（可能是一句断言、一组数字、一个方案、一篇"科普"）拆开，分别回答三件事：① 它声称的事实站不站得住；② 就算事实站得住，推理对不对；③ 我到底能信到什么程度。

## 为什么这么设计

绝大多数"有问题的说法"不是因为单点造假，而是三种东西混在一起：

- **事实**（能查、能证伪）
- **结论**（从事实推出来的）
- **价值判断**（"好/坏""应该/不应该"，没有对错，只有立场）

不先剥开这层，核查就会跑偏：要么对着价值判断找"证据"（永远找不着），要么事实错了却只争论结论（打偏）。所以第一步永远是拆解，不是查。

第二步查事实，第三步查推理。很多人只做第二步——把"事实"证伪就停了，却没发现即使事实全对，结论也推不出来（偷藏假设、相关当因果）。所以第三步必须**独立于事实真假**地检验推导。

## 流程

### 0. 锁定核查对象

- 要求用户提供**完整原文**（不要转述、不要提炼）；如果是图片 / 截图 / 链接，先提取其中的文字再开始。
- 若用户只给了结论、没给支撑它的事实或数据，明确标注"这是结论而非事实，核查将先反推它依赖哪些事实，并把这些事实列为待验证项"。
- 一句话确认核查范围（针对整段，还是只核其中某一句 / 某个数字），避免跑太宽。

### 1. 三层拆解

用表格把说法逐句 / 逐点拆成三类，并标注归属：

| 原文摘录 | 类型 | 说明 |
|---|---|---|
| …… | 事实 | 可外部验证的陈述 |
| …… | 结论 | 由事实推出 |
| …… | 价值判断 | 立场 / 偏好，无对错 |

关键动作：很多句子表面是"事实"实际夹带了结论（如"XX 增长迅猛"——"迅猛"是判断）。要把这类剥开，拆成"XX 同比增长 X%（事实）" + "迅猛（价值判断）"。

> **示例**：说法"国产新能源车销量暴涨，说明燃油车马上要被淘汰了。"
> - 事实：国产新能源车销量同比增长 X%（待查具体数字与时间）
> - 结论：燃油车马上要被淘汰
> - 价值判断：（隐含）"淘汰"是负面 / 应当发生的事
> 剥离后可知，核查重点应是"销量增长数字是否属实"以及"销量增长能否推出'马上淘汰燃油车'"两件事，而非争论淘汰好不好。

### 2. 事实核查（逐条联网验证）

对"事实"类每一条，用 WebSearch / WebFetch 查**来源、样本、时间、完整上下文**。禁止只凭训练记忆下结论；联网是默认动作，不是可选项。

逐条打五档标签，且**每条必须附带置信依据**（来源 + 样本规模 + 时间点），不能只贴标签：

1. **已证实** —— 有一手 / 权威来源直接支撑，样本与口径清晰
2. **基本成立，但需要收窄** —— 大方向对，但范围 / 比例 / 时间 / 适用条件被夸大或泛化（给出收窄后的准确表述）
3. **存在争议** —— 不同权威来源结论冲突，或学界 / 业界未达成共识（列双方）
4. **证据不足** —— 找不到可靠来源支撑，或仅有孤证、匿名、营销号转述
5. **明显错误** —— 有可靠反证（必须给出反证来源，否则不得标此档）

核查纪律：

- 区分**一手来源**（原始数据、官方文件、论文）与**二手转述**；转述降级一档置信。
- 数据 / 估值类必须标明**样本与时间点**——拿三年前的数据当现状是一类高发错误。
- 若来源本身有立场（厂商白皮书、advocacy 报告），明确标注其利益关联后再采信。

### 3. 推理链检验（假设事实全部成立）

这一步**不依赖**第二步的真假结论，专门检验"即使前提都对，推导成立不成立"：

1. **充分性**：这些事实真的能推出当前结论吗？还是只覆盖了必要条件、跳了一步？
2. **隐藏假设**：推导过程中有没有"默认成立但没验证"的前提？（列出来，逐条标注是否可靠）
3. **相关 ≠ 因果**：有没有把两件事同时发生当成"因为 A 所以 B"？（提示替代解释：共同第三因、反向因果、巧合）
4. **遗漏他因 / 关键信息**：有没有被忽略的、能推翻或削弱结论的因素？
5. **成立条件**：结论在哪些边界条件下成立？在哪些条件下直接失效？（给出"当且仅当……时成立"的精确表述）

### 4. 输出核查报告

严格按以下四段式模板输出（markdown）。面向非技术读者，避免术语堆砌；提到"相关不等于因果""隐藏假设"等概念时，用一句话给出业务含义。

```markdown
# 事实核查报告：[一句话概括被核查说法]

## 一、可信事实 vs 需修正事实
- ✅ 可信：……
- 🔧 需修正：……（原说法 → 修正后准确表述）
- ❌ 剔除 / 存疑：……

## 二、推理链最关键漏洞
[指出 1–3 个最致命的问题：偷藏假设 / 相关当因果 / 遗漏他因 / 概念偷换 / …，每条说明它为何致命]

## 三、补强后的最合理版本
[在承认可信事实 + 修补漏洞后，重写这则说法，让它经得起推敲。明确写出改了什么、为什么]

## 四、当前可信程度
- 总体评级：[高 / 中 / 低 / 暂不可信]
- 理由：……
- 还差什么才能更可信：……（具体要补的证据 / 口径）
```

评级口径：高 = 事实基本可证且推理无致命漏洞；中 = 事实多半成立但推理有可修补的薄弱点；低 = 关键事实存疑或推理核心断裂；暂不可信 = 核心事实被可靠反证或完全无来源。

## 硬规则清单

1. 🔴 **先拆解后核查**：未做三层拆解不得进入查事实，防止把价值判断当事实证伪。
2. 🔴 **事实核查必须联网且附依据**："明显错误"档若无可靠反证来源，不得标注；空贴标签视为未完成。
3. 🔴 **推理检验独立于事实真假**：即使事实全错，也要单独评估"若事实为真，结论推得动吗"。
4. 🟡 **数据必标样本与时间**：未标注时间点的数据类结论，默认提示"可能已过时"。
5. 🟡 **利益相关来源须标注**：厂商 / 机构自证类来源，明确其立场后再采信。
6. 🟢 **结论给可信程度而非对错**：输出必须落到"我能信到什么程度"，不替用户做价值决断。

## 依赖

- 联网能力：WebSearch / WebFetch（核查事实的默认动作）
- 无需其他子 skill；纯分析流程。
